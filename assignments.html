Course Assignments

Three homeworks that build one agent and then turn it on itself. You implement a ReAct loop by hand, give it tools over MCP and Skills, then write deterministic critics that judge what an agent produces — a decomposition, and the tests that claim to cover it.

HW1 Lectures 01 · 02 · 03

Build a Coding Agent From Scratch

Implement the ReAct tool-use loop by hand, with no agent framework. You write the ten step methods — prepare_context, call_llm, process_response, call_tools, and the rest — plus run() that ties them together. A FakeLLMClient returns scripted responses so every test is deterministic; the same code can drive a real model as an optional, ungraded extension.

agent/core.py agent/tools.py pytest.ini tests/
HW2 Lecture 03 · builds on HW1

Extend Your Agent with MCP and Skills

Add two new sources of behavior without touching the agent at all. Discover and call tools hosted by a separate MCP server over JSON-RPC/stdio, and inject on-disk SKILL.md instructions into the system prompt only when a request matches a trigger keyword. The payoff: an MCP-wrapped tool satisfies the exact same Tool protocol from HW1, so local and remote tools live in one dict interchangeably.

agent/mcp_client.py agent/skills.py fixtures/mcp_server/ fixtures/skills/
HW3 Lectures 06 · 11 · builds on HW2

Requirements Analysis & Compliance Verification

Two deterministic critics that judge what an agent produces — pure Python, no LLM at grading time. The first asks whether a decomposition is sound: it catches uncovered requirements, ambiguous or untestable tasks, circular and dangling dependencies, duplicate ids, and scope creep, using normalized keyword overlap, set logic, and textbook DFS over the dependency graph.

The second closes the loop by asking whether an implementation and its tests actually comply with that decomposition. Using dynamic call tracing (sys.setprofile) rather than static analysis, it catches the dishonest cases — a test that imports a function but never calls it, a task whose target was never written, a test that touches none of the tasks it claims to validate.

agent/requirements_critique.py agent/traceability.py fixtures/ tests/

How grading works. Each homework ships with a public test suite and a hidden autograder that checks exact output — follow each function's docstring contract precisely. Homeworks run entirely offline against deterministic fixtures, so a bug in one submission never cascades into the next: HW2 and HW3 each carry forward the pieces they depend on already solved.
